· plano de dados e controle

Recursos da configuração autenticada, não uma confirmação de conectividade. Selecione um nó para inspecionar a etapa; nenhuma operação é executada pelo diagrama.

    Preview não é o payload publicado. O parser lê o landing para gerar JSON de inspeção. O publicador na mesma aplicação envia envelopes com registros brutos; o SyncEngine faz parsing novamente na aplicação.

    Plano de controle

    • Ramificação das etapas → Azure Blob Storage, contêiner de controle: manifesto da execução, lease de exclusão mútua e checkpoint.
    • Aplicação durável no Cosmos DB → só então checkpoint. Entrega at-least-once com idempotência por accountId e versão.
    • sourceVersion ordena a origem; previousVersion valida o estado anterior. O ETag do Cosmos DB protege a escrita concorrente; não é a versão da origem nem o offset do Event Hubs.
    • O consumidor é acionado pelo clique na etapa 05. Não há loop automático de consumo nesta demonstração.

    Rede e identidade

    Desenho do template guiado; não é teste de conectividade

    • Navegador → HTTPS + sessão autenticada → Azure Container Apps.
    • Managed Identity + RBAC para acesso aos serviços.
    • VNet + Private Endpoints + DNS privado para Blob Storage, Cosmos DB e Event Hubs.
    • Suporte do template: Azure Container Registry (imagem) e Log Analytics (logs). Nomes de instâncias não são presumidos.
